# v0.2.4 task-filter TDD evidence

## Source and user journeys

No external plan file was used. The journeys came from community PR #7 and
maintainer review of its first implementation:

1. As an independent tester, I want to select one known benchmark task so that
   a useful smoke test costs only one baseline/optimized pair.
2. As a tester resuming a partial filtered run, I want every denominator and
   continuation command to preserve that task scope.
3. As a maintainer, I want a filtered run to fail closed when its ledger already
   contains unrelated tasks so that evidence from different scopes is not mixed.

Routing stayed local. The parser, live runner, tests, contributor branch, and
release flow are tightly coupled, so delegation did not pass the 25% economic
gate. No worker model was requested or used; token usage is unknown.

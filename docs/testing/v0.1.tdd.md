## Process-level isolation

E2E tests launch a separate fake Codex executable that implements JSONL usage,
prompt-input debugging, and app-server account/rate-limit responses. This
validates process arguments, parsing, failure handling, quota integration, and
receipt output without consuming a real model quota or depending on a network
account.

The local Windows desktop package exposed an internal `codex.exe` path that the
terminal could not execute (`Accesso negato`). That does not affect the static
CLI, audit, map, profile, lockfile, build, or test results. Real `ctxray run` and
`quota` usage on that machine requires the public `@openai/codex` CLI to be
installed and callable.

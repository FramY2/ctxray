# v0.2.3 community reproduction TDD evidence

## Source and user journeys

No external plan file was used. The journeys came from the observed activation
failure in Issue #1:

1. As an independent tester, I want one command to create a fresh two-turn
   ledger so that committed maintainer results are never mistaken for my run.
2. As a tester who passes the preflight, I want to resume the same ledger for
   all 20 turns without repeating completed calls.
3. As a maintainer, I want a bounded share report and checksums so that I can
   inspect evidence without treating self-reported independence as certified.

Routing stayed local. The benchmark runner, its tests, documentation, and
release surface are tightly coupled; delegation did not pass the 25% economic
gate. Requested and actual worker model/effort are therefore not applicable;
usage measurement is unknown and no savings claim is made for this development
run.

The automated suite does not spend a real user's Codex quota. A community
preflight intentionally performs two live turns only when a tester explicitly
runs `npm run benchmark:reproduce`. That run cannot be counted as independent
until the maintainer verifies that it came from an unrelated environment.

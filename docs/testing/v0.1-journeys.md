# CtxRay v0.1 user journeys

These journeys define the acceptance scope for the first public release.

1. As a Codex user, I want to see which local configuration sources consume
   context so I can remove bloat without exposing my conversations.
2. As a Codex user, I want to inspect the exact model-visible prompt structure
   when Codex exposes it so I can debug unexpected instructions.
3. As a user with a ChatGPT subscription, I want a post-turn receipt that never
   presents an API-equivalent amount as money I was charged.
4. As an API-key user, I want a dated token-based price estimate so I can spot
   expensive turns while understanding what the estimate omits.
5. As a power user, I want editable model and reasoning profiles compiled to
   native Codex files so I can change modes without hand-editing TOML.
6. As a maintainer, I want a redacted capability lockfile so I can reproduce a
   run's configuration without committing secrets or chat history.
7. As a new user, I want one CLI command to run Codex and append the local
   receipt after the final answer, even if quota lookup is unavailable.

## Acceptance rules

- Subscription output never contains “charged” or “spent” next to an API
  equivalent, except the explicit phrase “not charged”.
- Missing usage and quota values remain `unknown`, not `0`.
- Exact token counts are taken only from a `turn.completed` runtime event.
- Cached tokens are not billed twice.
- Profiles are deterministic and default to dry-run/staged output.
- Lockfiles redact secret-like keys before hashing or serializing values.
- The CLI critical path is covered by a process-level end-to-end test.

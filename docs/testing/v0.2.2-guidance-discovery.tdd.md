# v0.2.2 Codex guidance discovery TDD evidence

## Source and journeys

The journeys were derived from external
[Issue #6](https://github.com/FramY2/ctxwise/issues/6) and checked against
OpenAI's documented and open-source Codex guidance-discovery behavior.

1. As a developer running CtxWise in a nested directory, I want the audit to
   include every active instruction file from the project root to that
   directory so the reported context matches Codex.
2. As a developer using overrides, fallback filenames, or a project-doc byte
   limit, I want CtxWise to apply the same precedence and budget.
3. As a developer creating a capability lock, I want unrelated sibling
   instructions excluded while active nested guidance is included.
4. As a developer with an empty global override, I want CtxWise to fall back to
   the normal global instructions.

## Primary RED

- Tests: nested audit chain, fallback/budget, CLI root markers, and active

  missing root/intermediate sources, ignored fallback settings, and unrelated
  sibling guidance in the lock.
- Checkpoint: `e40748b test: reproduce nested Codex guidance discovery`.

- Commands: the same targeted test command and `npm run typecheck`.
